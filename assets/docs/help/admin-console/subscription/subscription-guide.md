### **구독결제(Subscription) 서비스 가이드**

상품·고객·구독을 등록해 두면, 청구일마다 인보이스를 만들고 등록된 카드로 결제까지 진행하는 서비스입니다. 관리자콘솔에서 구독결제를 설정하고 운영하는 방법을 안내합니다.

- 대상 : 구독결제를 이용하는 고객사 운영 담당자
- 결제수단 : 카드 자동이체
- 결제통화 : KRW · USD · JPY

## **1. 서비스 개요**

### **구독결제 서비스란**

구독결제는 고객과 맺은 정기 계약을 바탕으로, 정해진 청구 일시마다 인보이스(청구서)를 만들고 고객이 등록한 카드로 바로 결제하는 서비스입니다. 청구일 계산, 할인 적용, 결제 결과 기록, 결제 실패 건 처리까지 관리자콘솔과 API 어디서든 같은 방식으로 다룰 수 있습니다.

고객사가 하는 일은 상품·고객·구독을 등록하는 것까지입니다. 그다음부터 청구일마다 인보이스를 만들고 결제하고 결과를 남기는 일은 포트원이 처리합니다.

**구독결제 흐름**

1. **상품 등록** (고객사 · 콘솔/API) : 요금제와 가격, 청구 주기
2. **고객 등록** (고객사 · 콘솔/API) : 이름, 이메일, 사업자번호
3. **카드 등록** (고객 · 결제창(SDK)) : 자동이체용 결제수단
4. **구독 등록** (고객사 · 콘솔/API) : 상품, 청구 기준 일시, 할인
5. **청구와 결제** (포트원 · 자동) : 청구일마다 인보이스 생성 후 즉시 결제, 웹훅 전송

상품·고객·구독은 고객사가 등록하고, 카드는 고객이 고객사 서비스 화면에서 직접 등록합니다.

#### **메뉴 위치**

- 경로 : 관리자콘솔 > 구독결제 > 상품 관리 · 고객 관리 · 구독 관리 · 인보이스 관리

구독결제 메뉴는 네 개의 하위 메뉴로 나뉩니다. 할인 규칙은 상품 관리에서 만들고, 구독 관리에서 각 구독에 적용합니다.

#### **용어 정리**

| 용어           | 설명                                                                    |
| ------------ | --------------------------------------------------------------------- |
| **상품**       | 고객에게 판매하는 요금제입니다. 매 주기 청구되는 **정기 상품**과 한 번만 청구되는 **일회성 상품**이 있습니다.    |
| **고객**       | 구독료를 내는 대상입니다. 고객 한 명이 여러 구독을 가질 수 있습니다.                              |
| **결제수단**     | 고객이 등록한 카드(카드 자동이체)입니다. 고객당 1개만 유효하며, 새로 등록하면 기존 카드를 대체합니다.           |
| **구독**       | 어떤 고객에게 어떤 상품을 언제마다 청구할지 정한 계약 단위입니다.                                 |
| **청구 기준 일시** | 구독의 청구 날짜와 시각입니다. 매 주기의 청구일은 이 기준으로 계산됩니다.                            |
| **인보이스**     | 회차마다 만들어지는 청구서입니다. 생성과 동시에 결제가 시도되며, 결제 결과가 상태로 기록됩니다.                |
| **회차**       | 구독이 몇 번째 청구인지를 나타냅니다. 인보이스는 회차당 하나씩 만들어집니다.                           |
| **할인**       | 정률(%) 또는 정액으로 정의하는 할인 규칙입니다. 상품 관리에서 만들어 구독에 적용하며, 적용 기간은 회차 수로 정합니다. |

## **2. 사용설명서**

### **상품 관리**

- 경로 : 구독결제 > 상품 관리

구독에 담을 상품과 할인 규칙을 등록하고 관리합니다. 상품 목록에서는 상품번호, 상품명, 요금유형, 결제통화와 가격, 구독자 수를 확인할 수 있습니다.

#### **상품 등록하기**

1. 상품 관리 화면 오른쪽 위의 **상품 등록**을 누릅니다.
2. 아래 항목을 입력합니다.
3. **저장**을 누르면 상품이 목록에 추가되고, 구독 등록 시 선택할 수 있습니다.

| 항목        | 설명                                                                |
| --------- | ----------------------------------------------------------------- |
| 상품번호      | 직접 입력하거나 비워 두면 자동으로 부여됩니다. 등록 후에는 바꿀 수 없습니다.                      |
| 상품명 (필수)  | 인보이스와 결제 결과 메일에 표시되는 이름입니다.                                       |
| 설명        | 내부 관리용 설명입니다.                                                     |
| 요금유형 (필수) | **정기**: 청구 주기(월간, 연간 등)마다 청구합니다. **일회성**: 한 번만 청구합니다(가입비, 교재비 등). |
| 결제통화 (필수) | KRW(원), USD(달러), JPY(엔) 중 하나를 선택합니다.                              |
| 가격 (필수)   | 선택한 통화 기준 금액입니다.                                                  |

<Callout icon="💡" title="참고사항" content="- KRW 상품은 할인 후 금액을 기준으로 부가세가 계산되어, 인보이스에 공급가액과 부가세가 나뉘어 표시됩니다. USD·JPY 상품은 부가세를 계산하지 않습니다.
- 한 구독에는 같은 통화의 상품만 함께 담을 수 있습니다." />

<Callout icon="❗" title="유의사항" content="요금유형과 청구 주기는 상품을 등록한 뒤에는 바꿀 수 없습니다. 바꿔야 한다면 새 상품을 등록해 주세요." />

#### **상품 보관하기**

더 이상 판매하지 않는 상품은 삭제 대신 **보관**합니다. 보관한 상품은 목록에서 숨겨지고 새 구독에서 선택할 수 없지만, 이미 그 상품을 구독 중인 고객에게는 계속 정상적으로 청구됩니다.

#### **상품 청구 중지하기**

상품 수정 화면에서 **청구 중지**를 켜면, 그 상품이 담긴 구독은 더 이상 인보이스가 생성되지 않습니다. 서비스 제공을 멈춰야 하는 상품의 청구를 한 번에 막을 때 사용합니다.

<Callout icon="❗" title="유의사항" content="청구 중지는 상품 단위가 아니라 그 상품이 담긴 **구독 전체**에 적용됩니다. 같은 구독에 다른 상품이 함께 담겨 있어도 그 구독의 인보이스는 생성되지 않습니다." />

상품을 판매만 멈추고 기존 고객에게는 계속 청구하려면 청구 중지 대신 [보관](#상품-보관하기)을 사용하세요.

### **고객 관리**

- 경로 : 구독결제 > 고객 관리

구독료를 낼 고객을 등록하고, 고객별 결제수단과 구독 현황을 확인합니다.

#### **고객 등록하기**

| 항목       | 설명                                                                      |
| -------- | ----------------------------------------------------------------------- |
| 고객번호     | 고객사에서 쓰는 회원번호를 입력하거나, 비워 두면 자동으로 부여됩니다.                                 |
| 고객명 (필수) | 인보이스에 표시되는 이름입니다.                                                       |
| 이메일      | 인보이스 메일(결제 완료, 완납, 결제 실패, 결제 취소)을 받을 주소입니다. 인보이스 메일 발송을 설정한 경우에만 필수입니다. |
| 휴대폰      | 선택 항목입니다.                                                               |
| 사업자번호    | 기업 고객이라면 입력합니다. 숫자 10자리 형식만 확인하며, 국세청 진위 확인은 하지 않습니다.                   |
| 메모       | 내부 관리용 메모입니다.                                                           |

#### **결제수단(카드) 등록과 해지**

결제수단은 **카드 자동이체**를 지원합니다. 카드는 관리자콘솔에서 직접 등록할 수 없고, 고객이 고객사 서비스 화면에서 포트원 결제창(SDK)을 통해 등록합니다.

- 고객당 유효한 카드는 1개입니다. 고객이 카드를 다시 등록하면 기존 카드를 대체합니다.
- 관리자콘솔의 고객 상세 화면에서는 등록된 카드를 **해지**만 할 수 있습니다.
- 카드를 해지해도 구독은 그대로 유지되지만, 카드가 다시 등록되기 전까지는 청구일이 와도 인보이스가 만들어지지 않습니다.

<Callout icon="💡" title="참고사항" content="카드가 없는 고객에게도 구독을 등록할 수 있습니다. 다만 청구 일시에 유효한 카드가 없으면 그 회차의 인보이스는 생성되지 않으며, 실패 기록도 남지 않습니다. 구독을 등록하기 전에 고객이 카드를 먼저 등록하도록 안내해 주세요." />

### **구독 관리**

- 경로 : 구독결제 > 구독 관리

고객에게 어떤 상품을 언제마다 청구할지 정합니다. 목록에서는 구독번호, 고객명, 구독 상품, 청구 기준 일시, 다음 인보이스 예정일, 최근 결제 결과, 구독 상태를 확인할 수 있습니다.

#### **구독 등록하기**

구독은 4단계 화면에서 등록합니다.

1. **고객 선택** : 구독할 고객을 검색해 선택합니다.
2. **상품 선택** : 구독에 담을 상품을 고릅니다. 한 구독에 담는 상품은 결제통화가 같아야 하고, 정기 상품은 청구 주기도 모두 같아야 하므로 조건이 다른 상품은 선택할 수 없게 비활성화됩니다. 일회성 상품은 통화만 같으면 어떤 주기와도 함께 담을 수 있습니다.
3. **구독 설정** : 구독번호(직접 입력 또는 자동 부여), 구독 종료일(선택), 인보이스 메일 종류별 발송 여부를 정합니다. **인보이스 미리보기**로 고객이 받을 메일을 확인할 수 있습니다.
4. **확인** : 입력한 내용을 확인하고 등록을 완료합니다.

<Callout icon="💡" title="참고사항" content="- 구독 종료일을 정하면 그날이 지난 뒤로는 인보이스가 만들어지지 않고 구독이 종료됩니다. 비워 두면 해지할 때까지 계속 청구됩니다.
- 상품이 하나도 없는 구독은 만들 수 없습니다. 구독을 수정할 때도 마지막 상품은 뺄 수 없습니다.
- 인보이스 메일 발송을 켜려면 고객 정보에 이메일이 등록되어 있어야 합니다.
- 1회차 결제에 실패한 구독은 미완료(Incomplete) 상태가 됩니다. 활성(ACTIVE) 상태로 전환되는 시점은 Subscription.Activated 웹훅으로 받을 수 있습니다." />

#### **청구일은 이렇게 정해집니다**

인보이스는 구독의 **청구 기준 일시**(날짜와 시각)를 기준으로 매 주기마다 만들어지고, 만들어지는 즉시 결제가 시도됩니다. 기준일이 29\~31일이면 그 날짜가 없는 달에는 그달 마지막 날에 청구하고, 다음 달에는 다시 원래 날짜로 돌아옵니다.

| 청구 기준일 | 1월     | 2월     | 3월     | 4월     | 5월     |
| ------ | ------ | ------ | ------ | ------ | ------ |
| 매월 31일 | 1월 31일 | 2월 28일 | 3월 31일 | 4월 30일 | 5월 31일 |
| 매월 30일 | 1월 30일 | 2월 28일 | 3월 30일 | 4월 30일 | 5월 30일 |
| 매월 15일 | 1월 15일 | 2월 15일 | 3월 15일 | 4월 15일 | 5월 15일 |

윤년이 아닌 해 기준입니다. 2월 28일로 당겨진 청구일이 이후에도 28일로 굳지 않고, 3월부터 다시 기준일로 돌아온다는 점이 핵심입니다.

#### **정기결제일 변경하기**

이미 결제가 시작된 구독은 결제 시작일을 바꿀 수 없습니다. 대신 구독 수정 화면의 **정기결제일 변경**에서 다음 결제일을 연-월-일로 지정하면, 그 날짜가 새 기준일이 되어 이후 청구일이 다시 계산됩니다. 청구 시각은 그대로 유지됩니다.

<Callout icon="💡" title="참고사항" content="일회성 상품만 담긴 구독은 반복 청구가 없으므로 정기결제일 변경을 사용할 수 없습니다." />

#### **일시정지, 재개, 해지**

| 작업       | 결과                                                                                             |
| -------- | ---------------------------------------------------------------------------------------------- |
| **일시정지** | 일시정지 기간에는 인보이스가 만들어지지 않습니다. 이 기간에는 할인 회차도 줄어들지 않습니다.                                           |
| **재개**   | 원래의 청구 기준 일시를 그대로 이어서 다음 청구일부터 청구합니다. 정지 기간만큼 청구일이 뒤로 밀리지 않으며, 정지 기간 중 지나간 회차를 몰아서 청구하지도 않습니다. |
| **해지**   | 즉시 구독이 종료되고 이후 인보이스는 만들어지지 않습니다. 이미 결제된 인보이스는 그대로 남습니다.                                        |

<Callout icon="❗" title="유의사항" content="결제 실패가 여러 번 이어져도 구독이 자동으로 일시정지되거나 해지되지 않습니다. 미납이 계속되는 구독을 멈출지는 고객사에서 판단해 일시정지 또는 해지해 주세요." />

### **할인**

첫 달 무료, 첫 3개월 20% 할인, 연간 약정 할인처럼 구독에 붙는 할인을 관리합니다. 할인은 상품 관리에서 **할인 규칙**을 먼저 만들고, 구독 관리에서 그 규칙을 구독에 적용하는 방식입니다. 하나의 할인 규칙을 여러 구독에 적용할 수 있습니다.

#### **할인 규칙 만들기**

- 경로 : 구독결제 > 상품 관리 > 할인 > 할인 등록

| 항목         | 설명                                                                                                      |
| ---------- | ------------------------------------------------------------------------------------------------------- |
| 할인명 (필수)   | 인보이스와 결제 결과 메일에 표시됩니다. 고객에게는 할인명만 보입니다.                                                                 |
| 할인 유형 (필수) | **정률**: 1\~100% 사이로 할인합니다. **정액**: 정한 금액만큼 뺍니다. 정액 할인은 통화(KRW·USD·JPY)를 함께 정하며, 같은 통화의 구독에만 적용할 수 있습니다. |
| 적용 범위 (필수) | **구독 전체**: 구독에 담긴 모든 상품 합계에 적용합니다. **특정 상품**: 고른 상품에만 적용합니다(예: 교재비는 빼고 수업료에만 10%).                      |
| 적용 기간 (필수) | **1회**: 다음 한 회차만. **N회**: 정한 회차 수만큼. **계속**: 구독이 끝날 때까지.                                                |
| 적용 마감일     | 이 날짜가 지나면 이 할인을 새 구독에 적용할 수 없습니다. 이미 적용된 구독에는 남은 회차만큼 계속 적용됩니다.                                         |

<Callout icon="❗" title="유의사항" content="한 번이라도 구독에 적용된 할인 규칙은 할인명과 적용 마감일만 수정할 수 있습니다. 할인율이나 기간을 바꾸려면 새 할인 규칙을 만들어 주세요. 쓰지 않을 할인은 삭제 대신 보관하며, 보관해도 이미 적용된 구독에는 남은 회차까지 유지됩니다." />

#### **구독에 할인 적용하기**

- 경로 : 구독결제 > 구독 관리 > 구독 상세 > + 할인 적용

1. 구독 관리에서 할인을 적용할 구독을 열고 **+ 할인 적용**을 누릅니다.
2. 적용할 할인 규칙을 선택합니다. 서로 다른 할인을 여러 개 함께 적용할 수 있지만, 같은 할인을 한 구독에 두 번 적용할 수는 없습니다.
3. 적용된 할인 목록에서 할인별 **남은 회차**와 **적용 범위**를 확인할 수 있습니다. 필요하면 여기서 할인을 제거합니다.

할인을 제거해도 이미 만들어진 인보이스의 금액은 바뀌지 않습니다.

#### **할인이 여러 개일 때 계산 순서**

한 상품에 할인이 겹치면 **정률 할인을 적용한 순서대로 먼저 곱하고**, 그다음 **정액 할인을 뺍니다**. 할인 후 금액이 0원보다 작아지지는 않습니다.

**계산 예시 · 월 50,000원 구독, 할인 3개 적용**

| 항목                     | 금액          |
| ---------------------- | ----------- |
| 정가                     | 50,000원     |
| 신규 가입 20% (정률, N회(3회)) | -10,000원    |
| 제휴 할인 10% (정률, 계속)     | -4,000원     |
| 이벤트 쿠폰 3,000원 (정액, 1회) | -3,000원     |
| **청구 금액**              | **33,000원** |

50,000원 × 0.8 = 40,000원 → × 0.9 = 36,000원 → - 3,000원 = 33,000원. 두 정률 할인을 합해 30%를 빼는 것이 아니라 차례로 곱합니다.

#### **무료 체험 기간 만들기**

별도의 체험 기간 설정 대신 **100% 정률 할인**으로 무료 체험을 만듭니다. 첫 달 무료라면 100% · 1회, 첫 3개월 무료라면 100% · N회(3회)로 할인 규칙을 만들어 구독에 적용하세요.

- 청구 금액이 0원인 인보이스는 카드 결제를 시도하지 않고 바로 결제 완료로 처리되며, 할인 회차는 1회 줄어듭니다.
- 체험 기간이 끝나면 다음 회차부터 정상 금액이 청구됩니다.

#### **할인 회차가 줄어드는 기준**

- 할인 회차는 인보이스가 실제로 만들어질 때 1회 줄어듭니다.
- 일시정지 기간처럼 인보이스가 만들어지지 않으면 회차도 줄어들지 않습니다.
- 인보이스를 취소하면 그 인보이스에서 사용한 할인 회차가 다시 돌아옵니다.

### **인보이스 관리**

- 경로 : 구독결제 > 인보이스 관리

회차마다 만들어진 인보이스와 결제 결과를 확인하고, 결제되지 않은 인보이스를 처리합니다. 인보이스번호, 구독번호, 고객번호, 고객명으로 검색할 수 있습니다.

**인보이스 관리 · 목록 예시**

| 상태       | 인보이스번호        | 고객명     | 청구 금액      | 결제 시도 일시         | 처리               |
| -------- | ------------- | ------- | ---------- | ---------------- | ---------------- |
| **결제완료** | INV-2026-0912 | 김민지     | 33,000원    | 2026-10-01 09:00 | 상세               |
| **수납중**  | INV-2026-0913 | 박서준     | 9,900원     | 2026-10-02 00:00 | 재시도 · 완납 처리 · 취소 |
| **완납**   | INV-2026-0898 | 그레이스리테일 | 1,080,000원 | 2026-09-28 14:00 | 상세               |
| **취소**   | INV-2026-0871 | 이도윤     | 29,000원    | 2026-09-15 10:30 | 재생성              |

예시 데이터입니다. 처리 버튼은 인보이스 상태에 따라 다르게 표시됩니다.

#### **인보이스 상태**

| 상태       | 의미                                                                     | 할 수 있는 처리      |
| -------- | ---------------------------------------------------------------------- | -------------- |
| **결제완료** | 청구 일시에 카드 결제가 성공했거나, 재시도로 결제가 성공한 인보이스입니다. 청구 금액이 0원인 인보이스도 여기에 해당합니다. | 상세 보기, 미리보기    |
| **수납중**  | 카드 결제가 실패해 아직 돈을 받지 못한 인보이스입니다.                                        | 재시도, 완납 처리, 취소 |
| **완납**   | 계좌이체 등 카드 결제 외의 방법으로 받은 대금을 담당자가 확인해 완납 처리한 인보이스입니다.                   | 상세 보기, 미리보기    |
| **취소**   | 수납중이던 인보이스를 취소한 상태입니다. 기록은 그대로 남습니다.                                   | 재생성            |

#### **결제 재시도**

고객이 카드 한도를 정리했거나 새 카드를 등록했다면, 수납중인 인보이스의 **재시도**를 눌러 다시 결제합니다. 여러 건을 선택해 한 번에 재시도할 수도 있습니다.

<Callout icon="💡" title="참고사항" content="결제가 실패해도 포트원이 자동으로 다시 시도하지는 않습니다. 결제 실패 메일을 켜 두면 고객이 실패 사실을 바로 알고 카드를 다시 등록할 수 있고, 결제 실패 웹훅(Invoice.PaymentFailed)으로 고객사 서비스에서 직접 안내할 수도 있습니다." />

#### **완납 처리(수기 수납)**

고객이 계좌이체처럼 카드가 아닌 방법으로 대금을 보냈다면, 입금을 확인한 뒤 해당 인보이스의 **완납 처리**를 누릅니다. 입금 확인 내용은 메모로 남길 수 있습니다(예: "10/5 계좌 입금 확인"). 완납 처리한 인보이스는 카드 결제 건과 같은 목록에서 함께 관리됩니다.

#### **취소와 재생성**

잘못 청구된 인보이스는 **취소**한 뒤 **재생성**합니다. 재생성하면 그 시점 구독의 최신 상태(상품, 할인)를 반영한 새 인보이스가 같은 회차로 만들어지고 바로 결제가 시도됩니다. 원래 인보이스는 취소 상태로 기록이 남습니다.

<Callout icon="❗" title="유의사항" content="- 취소는 수납중인 인보이스에만 할 수 있습니다.
- 결제가 시도된 인보이스(결제완료, 수납중, 완납)의 금액은 나중에 수정할 수 없습니다. 구독의 상품이나 할인을 먼저 고친 뒤 취소와 재생성으로 바로잡아 주세요." />

#### **수동 청구**

정기 청구일이 아닌 때에 추가로 청구해야 한다면 구독 상세의 **수동 청구**를 사용합니다. 등록된 상품을 고르거나, 항목명·단가·수량을 직접 입력하면 인보이스가 한 건 만들어지고 바로 결제가 시도됩니다.

#### **인보이스 메일과 미리보기**

인보이스의 결제 결과는 고객 이메일로 안내할 수 있습니다. 메일에는 고객사 로고, 상품, 정가와 할인, 최종 금액이 표시됩니다. 어떤 메일을 보낼지는 고객사가 정하며, 구독 등록·수정 화면에서 메일 종류별로 발송 여부를 켜고 끌 수 있습니다.

| 메일           | 보내는 시점                        | 고객에게 알리는 내용                                |
| ------------ | ----------------------------- | ------------------------------------------ |
| **결제 완료 메일** | 카드 결제 성공, 재시도 성공              | 결제된 금액과 내역(영수증 역할)                         |
| **완납 메일**    | 담당자가 완납 처리했을 때                | 대금 수납이 확인되었다는 사실과 내역                       |
| **결제 실패 메일** | 카드 결제 실패                      | 결제되지 않은 금액과 내역, 고객사 서비스에서 결제수단을 다시 등록하는 방법 |
| **결제 취소 메일** | 고객사가 결제된 인보이스의 결제를 취소(환불)했을 때 | 취소된 결제 금액과 내역                              |

<Callout icon="💡" title="참고사항" content="결제 취소 메일은 이미 받은 대금을 돌려줄 때 발송됩니다. 결제되지 않은(수납중) 인보이스를 취소하는 것은 대금이 오가지 않으므로 결제 취소 메일이 발송되지 않습니다." />

결제 실패 메일을 받은 고객은 카드 한도나 유효기간 문제를 확인하고, 결제수단을 다시 등록할지 스스로 판단할 수 있습니다. 고객이 카드를 다시 등록하면 수납중인 인보이스를 [재시도](#결제-재시도)해 결제를 마무리하세요.

<Callout icon="💡" title="참고사항" content="청구 일시에 카드가 아예 등록되어 있지 않으면 인보이스가 만들어지지 않으므로 결제 실패 메일도 발송되지 않습니다." />

인보이스 상세의 **인보이스 미리보기**로 고객이 받는 메일을 상태별로 그대로 확인할 수 있고, **PDF 다운로드**로 인보이스를 내려받을 수 있습니다.

### **웹훅으로 상태 받기**

고객, 구독, 인보이스의 상태가 바뀔 때마다 고객사 서버로 웹훅이 전송됩니다. 관리자콘솔에서 처리했든 API로 처리했든 같은 웹훅이 전송되므로, 웹훅만으로 고객사 시스템의 상태를 맞출 수 있습니다.

| 이벤트                                                                  | 보내는 시점                                                                                           |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `Customer.Created` · `Customer.Updated`                              | 고객 생성, 수정                                                                                        |
| `Customer.PaymentMethodRegistered` · `Customer.PaymentMethodRevoked` | 카드 등록(교체 포함), 카드 해지                                                                              |
| `Subscription.Created` · `Subscription.Updated`                      | 구독 생성(사전 등록 포함), 수정                                                                              |
| `Subscription.DiscountAdded` · `Subscription.DiscountRemoved`        | 할인 적용, 제거                                                                                        |
| `Subscription.Paused` · `Subscription.Resumed`                       | 일시정지, 재개                                                                                         |
| `Subscription.Incomplete` · `Subscription.Activated`                 | 1회차 결제 실패, 활성(ACTIVE) 상태로 전환                                                                     |
| `Subscription.Ended`                                                 | 해지, 일회성 상품 결제 완료, 종료일 도달                                                                         |
| `Invoice.Paid`                                                       | 결제 성공, 재시도 성공, 0원 인보이스, 완납 처리, 결제창 등록 결제                                                         |
| `Invoice.PaymentFailed` · `Invoice.Canceled` · `Invoice.Regenerated` | 결제 실패, 인보이스 취소, 재생성. 재생성한 인보이스의 결제 결과는 별도 웹훅(`Invoice.Paid` 또는 `Invoice.PaymentFailed`)으로 전송됩니다. |

<Callout title="개발자 가이드 보러가기↗" />

웹훅 수신 설정과 페이로드 형식은 포트원 개발자센터에서 확인할 수 있습니다.
